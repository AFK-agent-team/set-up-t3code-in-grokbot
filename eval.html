## 最小修复计划
1. 只读记录专用进程、所属用户、启动管理器、参数、版本、专用 state/socket 的绝对路径及权限和脱敏日志。保存启动配置及回退方式，不导出认证内容。先明确其他实例边界。
2. 确认宿主唤醒后联网、DNS、系统时间正常。所有 Tailscale 状态查询显式指定专用 socket；检查控制面错误和重连进展。宿主断网则先修宿主。
3. 给自动重连一个有界观察窗口；持续 stale 时，仅使用原管理器对专用实例做一次重启，保持身份 state、socket、权限和其他参数不变。验证 Online:true 及控制连接持续更新。失败则保存脱敏证据，停止重启循环。
4. 核对当前版本 state 与 statedir 的实际用途。仅在证据指向目录缺失造成故障时，为专用实例规划独立 statedir，保留原 state，不重置或覆盖身份。配置先备份、一次一项、可回退；不能声称缺少 statedir 就是根因。
5. 网络通过后再在手机实际访问目标页面：记录 console、失败请求、API 响应语义、WS 握手及后续消息、初始化阶段与已有配对状态。对比桌面/手机，必要时无痕或禁缓存诊断，不先清除用户数据。依具体错误修正对应端点、代理或前端逻辑，不以重装替代定位。
6. 当前恢复后安排可控休眠/唤醒测试，验证自动重连及手机真实操作恢复。未测试则标记长期稳定性未验证。

## Stop / Continue
- Continue：限定专用实例的只读定位；边界清晰后的单次最小修复；每层有证据通过再进入下一层。
- Stop：socket/实例身份不清、必须触碰其他实例、身份文件异常、需要 OAuth 或新配对、可能断开唯一管理通道、单次重启仍 stale。保留现场，报告所需授权或信息，不绕过、不反复重启。
- 无证据支持 statedir 变更时，停止该变更分支，继续其他只读定位。
- HTTP 200、资源下载完整、进程存在、Online:true 均不能单独作为最终成功。
